# Проверка перегруженной модели

1. Найди публичные методы, их данные, вызывающие места и тесты. Если в Git нет истории, не выдумывай churn.
2. Сгруппируй независимые инварианты, зависимости и причины изменения. Длина файла сама по себе не обосновывает перенос.
3. Оставь естественное поведение в модели; устойчивую самостоятельную роль выдели рядом в namespace. Не разрезай на concerns по типу Rails-макроса.
4. Переноси одну роль за раз, сохраняя публичный сценарий и тесты.

Результат: что мешает конкретному изменению, какую ответственность выделяем и как проверяем сохранение поведения.
